## 1. 페르소나 개요

Polaris는 **"목표를 세우는 것부터 부담스러운 사람들"**을 위한 서비스입니다.

### 1.1 타겟 사용자 특징

```
공통점:
- 거창한 목표 세우기가 부담스럽다
- 혼자서는 루틴을 오래 유지하기 어렵다
- 작은 행동도 누군가 알아봐주면 좋겠다
- 캐릭터/게임 요소에 친숙하다

차이점:
- 무기력의 원인 (학업 압박 vs 업무 소진 vs 사회적 고립)
- 가용 시간대 (오전 vs 저녁 vs 불규칙)
- 선호하는 미션 강도 (아주 작은 것 vs 조금 도전적인 것)
```

### 1.2 페르소나 선정 기준

| 기준 | 설명 |
|------|------|
| **기능 연결성** | 각 페르소나는 핵심 기능과 자연스럽게 연결되어야 함 |
| **시나리오 다양성** | 서로 다른 사용 패턴을 보여야 함 |
| **기술 검증** | 백엔드 아키텍처의 주요 기능을 검증할 수 있어야 함 |

## 2. 페르소나 #1: 무기력한 대학생 "지우"

### 2.1 기본 정보

| 항목 | 내용 |
|------|------|
| 이름 | 김지우 |
| 나이 | 23세 |
| 직업 | 대학생 (휴학 중) |
| 거주 형태 | 자취 (원룸) |
| 생활 패턴 | 늦게 자고 늦게 일어남 (새벽 2시 취침, 오후 12시 기상) |
| 성격 | 내향적, 완벽주의 성향, 자기 비판적 |

### 2.2 Goal (앱에서 이루고 싶은 것)

```
"오늘 하루를 그냥 흘려보내지 않았다는 증거가 필요해요."

- 작은 행동이라도 했다는 기록을 남기고 싶다
- 캐릭터가 나를 기다려준다는 느낌을 받고 싶다
- 거창한 목표 없이도 하루를 시작하고 싶다
```

### 2.3 Pain Points

- 아침에 일어나도 뭘 해야 할지 막막함
- 할 일 앱은 너무 딱딱하고 압박감이 듦
- 혼자 목표를 세우면 지키지 못할 것 같아서 아예 안 세움
- 하루 종일 침대에 누워있으면 죄책감이 듦

### 2.4 주요 사용 시나리오

#### 시나리오 1: 첫 미션으로 하루 시작하기

```
[오후 1시, 막 일어남]

1. 핸드폰을 보니 노바가 알림을 보냄
   "오늘도... 작은 별 하나 만들까?"

2. 앱을 열면 미션 1개가 제안됨
   "물 한 컵 마시기 (1분, 별조각 5개)"

3. 거절 버튼을 누름 (귀찮음)
   → 노바: "괜찮아. 그럼 다른 별 찾아볼게."

4. 다음 미션 확인
   "창문 3분 열기 (3분, 별조각 7개)"

5. 이건 할 수 있을 것 같아서 완료 버튼 클릭

6. 노바가 질문 1개 제시
   "창문을 열었을 때 어떤 소리가 들렸어?"

7. "차 소리랑 바람 소리"라고 답변

8. 노바: "그 소리를 기억해둘게. 오늘 별 하나 생겼어."
   → 별조각 +7 획득

9. 캐릭터 상태 확인
   → affection이 조금 올라감
   → 노바가 조금 더 밝아 보임
```

**연결되는 기능:**
- ✅ AI 미션 사전 생성 (사용자 설문 기반 개인화)
- ✅ 미션 거절 및 다음 미션 제안
- ✅ 미션 완료 1문항 답변
- ✅ 별조각 지급 (이벤트 기반)
- ✅ 캐릭터 상태 변화

**검증되는 기술:**
- Spring Event 기반 비동기 처리
- Redis 캐시 조회 (미션 스택)
- gRPC 읽기 (캐릭터 상태 조회)

#### 시나리오 2: 캐릭터 돌보기로 애착 형성

```
[저녁 8시, 하루 종일 미션 안 함]

1. 앱을 열면 노바가 쓸쓸한 표정
   → affection 수치가 낮아짐 (시간 경과)

2. 상태 확인
   - 포만감: 출출함 (40/100)
   - 기운: 말짱함 (80/100)
   - 애정: 쓸쓸함 (25/100)

3. "밥 주기" 버튼 클릭
   → 별조각 3개 차감
   → 포만감 +30

4. 노바: "먹는 중... 빛도 맛이 있구나."

5. "놀아주기" 버튼 클릭
   → 별조각 2개 차감
   → 애정 +25

6. 노바가 다시 밝아짐
   → 캐릭터 이미지가 IDLE 상태로 변경
```

**연결되는 기능:**
- ✅ 캐릭터 상태 시간 감쇠
- ✅ 돌봄 액션 (별조각 소비)
- ✅ 상태별 캐릭터 이미지 변화

**검증되는 기술:**
- 트랜잭션 관리 (별조각 차감 + 상태 증가)
- 이벤트 발행 (CareActionCompletedEvent)
- character_assets 조회 (상태별 이미지)

#### 시나리오 3: SNS 공유로 작은 자랑하기

```
[밤 11시, 오늘 미션 3개 완료]

1. 홈 화면에서 "공유" 버튼 클릭

2. 캐릭터 카드 생성
   - 노바 이미지 (현재 장착 스킨)
   - "오늘의 별조각 +25"
   - "오늘도... 작은 별 하나 만들었어."

3. "공유하기" 버튼 클릭
   → Web Share API 호출
   → 인스타그램 스토리에 공유

4. 공유 완료 후 별조각 +10 획득
   (하루 1회 제한)

5. 업적 달성 알림
   "오늘의 자랑 (캐릭터 카드 공유 1회)"
   → 별조각 +10 추가 획득
```

**연결되는 기능:**
- ✅ SNS 카드 생성
- ✅ 공유 이벤트 기록
- ✅ 공유 보상 (하루 1회 제한)
- ✅ 업적 시스템

**검증되는 기술:**
- 중복 방지 로직 (하루 1회)
- 이벤트 체이닝 (ShareCompletedEvent → AchievementUnlockedEvent)
- 트랜잭션 정합성 (별조각 지급)

## 3. 페르소나 #2: 루틴 없는 직장인 "민준"

### 3.1 기본 정보

| 항목 | 내용 |
|------|------|
| 이름 | 이민준 |
| 나이 | 29세 |
| 직업 | IT 스타트업 개발자 |
| 거주 형태 | 자취 (오피스텔) |
| 생활 패턴 | 불규칙 (야근 많음, 주말 보상 수면) |
| 성격 | 효율 추구, 완벽주의, 번아웃 경험 |

### 3.2 Goal (앱에서 이루고 싶은 것)

```
"일 외에 나를 돌보는 시간이 필요해요."

- 퇴근 후 침대에 쓰러지는 패턴을 바꾸고 싶다
- 작은 자기 관리 루틴을 만들고 싶다
- 업무 스트레스를 풀 수 있는 가벼운 활동이 필요하다
```

### 3.3 Pain Points

- 퇴근 후 너무 피곤해서 아무것도 하기 싫음
- 주말에 몰아서 쉬려고 하면 더 피곤함
- 운동/독서 같은 목표는 너무 부담스러움
- 회사 일정 관리 앱은 충분히 쓰고 있어서 또 다른 할 일 앱은 싫음

### 3.4 주요 사용 시나리오

#### 시나리오 1: 퇴근 후 작은 미션으로 전환

```
[저녁 8시, 퇴근 후 집 도착]

1. 현관에서 신발 벗으며 핸드폰 확인
   → 쪼리가 알림 보냄
   "현관까지 가볼래? 쪼리 기준 원정임."

2. 앱을 열면 미션 제안
   "현관까지 다녀오기 (2분, 별조각 8개)"

3. "이미 현관인데?" 하며 웃음
   → 완료 버튼 클릭

4. 쪼리가 질문
   "오늘 바깥 공기는 어땠어?"

5. "퇴근길 지하철 냄새"라고 답변

6. 쪼리: "했다? 그럼 됐음."
   → 별조각 +8 획득

7. 다음 미션 확인
   "목·어깨 10초 돌리기 (1분, 별조각 5개)"

8. 소파에 앉아서 어깨 돌림
   → 완료 후 "어깨가 조금 가벼워진 것 같아?" 질문
   → "응" 답변

9. 연속 미션 완료 업적 달성
   "작은 루틴의 시작 (일일 미션 3회)"
   → 별조각 +15 추가 획득
```

**연결되는 기능:**
- ✅ 시간대별 미션 추천 (저녁 시간대)
- ✅ 연속 미션 완료 (업적 시스템)
- ✅ 캐릭터별 말투 차별화

**검증되는 기술:**
- AI 미션 생성 시 시간 컨텍스트 반영
- 업적 진행도 계산 (실시간)
- 이벤트 체이닝 (MissionCompleted → AchievementProgress)

---

#### 시나리오 2: 아이템 구매로 캐릭터 꾸미기

```
[주말 오후, 별조각 80개 모음]

1. 상점 탭 클릭
   → 스킨/배경/소모품 목록 조회

2. "밤하늘 스킨" 클릭 (80 별조각)
   → 미리보기: 쪼리가 어두운 배경에서 빛남

3. 구매 버튼 클릭
   → 별조각 80개 차감
   → user_items에 스킨 추가

4. 인벤토리에서 "밤하늘 스킨" 장착
   → 캐릭터 이미지 변경

5. 홈 화면에서 변경된 쪼리 확인
   → "오, 분위기 바뀌네"

6. 캐릭터 카드 생성 후 SNS 공유
   → 공유 보상 별조각 +10

7. 업적 달성
   "첫 스킨 (스킨 1개 보유)"
   → 별조각 +10 추가 획득
```

**연결되는 기능:**
- ✅ 아이템 구매 (1회 구매 제한)
- ✅ 아이템 장착
- ✅ 캐릭터 이미지 변경
- ✅ 중복 구매 방지

**검증되는 기술:**
- 트랜잭션 관리 (별조각 차감 + 아이템 추가)
- 유니크 제약 (user_id + item_id)
- character_assets 조회 (스킨별 이미지)

#### 시나리오 3: 알림 설정으로 루틴 만들기

```
[일요일 밤, 다음 주 준비]

1. 마이페이지 → 알림 설정

2. 알림 시간대 변경
   - 오전 알림: OFF
   - 저녁 알림: ON (19:00)
   - 밤 알림: ON (22:00)

3. 알림 우선순위 설정
   - 미션 제안 알림: ON
   - 캐릭터 상태 알림: ON
   - 업적 알림: OFF

4. 설정 저장
   → user_notification_settings 업데이트

5. 월요일 저녁 7시
   → Web Push 알림 도착
   "쪼리가 오늘의 원정을 준비했어요"

6. 앱 열어서 미션 확인
   → "책상 위 물건 하나 치우기"

7. 완료 후 별조각 획득
   → 루틴 형성 시작
```

**연결되는 기능:**
- ✅ 알림 설정 (시간대별)
- ✅ Web Push 알림 발송
- ✅ 알림 우선순위 관리

**검증되는 기술:**
- 스케줄러 기반 알림 발송
- Web Push API 통합
- 사용자별 알림 설정 조회

| 거주 형태 | 자취 (원룸) |
| 생활 패턴 | 불규칙 (프로젝트에 따라 변동) |
| 성격 | 감성적, 외향적이지만 혼자 있는 시간 많음 |

### 4.2 Goal (앱에서 이루고 싶은 것)

```
"혼자 있어도 누군가 나를 기다려주는 느낌이 필요해요."

- 말 없는 위로를 받고 싶다
- 작은 행동을 알아봐주는 존재가 필요하다
- 캐릭터와의 관계를 통해 외로움을 달래고 싶다
```

### 4.3 Pain Points

- 재택근무로 사람과의 접촉이 적음
- 혼자 있으면 무기력해지고 우울해짐
- 친구에게 연락하기엔 부담스러움
- 반려동물을 키우고 싶지만 여건이 안 됨

### 4.4 주요 사용 시나리오

#### 시나리오 1: 무무와의 조용한 교감

```
[오전 11시, 프로젝트 마감 후 무기력]

1. 침대에 누워 핸드폰 확인
   → 무무가 알림 보냄
   "무..."

2. 앱을 열면 무무가 쓸쓸한 표정
   → affection 수치 낮음 (20/100)

3. 상태 확인
   - 포만감: 배고픔 (15/100)
   - 기운: 피곤함 (30/100)
   - 애정: 쓸쓸함 (20/100)

4. "밥 주기" 클릭
   → 별조각 3개 차감
   → 무무: "무...! (얌)"

5. "재우기" 클릭 (무료)
   → 무무: "무... 자."
   → 무무가 눈을 감음

6. 10분 후 다시 앱 실행
   → 무무가 일어나서 조금 밝아짐
   → affection +5 자동 증가

7. 미션 확인
   "오늘 기분 한 단어 적기 (2분, 별조각 6개)"

8. 완료 후 질문
   "오늘 기분을 한 단어로 적으면 뭐야?"
   → "텅 빔" 답변

9. 무무: "무우..."
   해석: 무무가 그 답변을 오래 기억할 것 같아요.

10. 별조각 +6 획득
    → 무무가 조금 더 밝아짐
```

**연결되는 기능:**
- ✅ 캐릭터 상태 시간 감쇠
- ✅ 돌봄 액션 (무료/유료)
- ✅ 캐릭터별 반응 차별화
- ✅ 감정 기록 미션

**검증되는 기술:**
- 상태 자동 감소 스케줄러
- 돌봄 액션 쿨다운 관리
- 캐릭터 말투 시스템 (무무 특화)

#### 시나리오 2: 출석으로 관계 쌓기

```
[매일 아침 10시, 7일 연속 출석]

1. 앱 실행
   → 출석 체크 팝업 자동 표시

2. "출석하기" 버튼 클릭
   → 캘린더에 별 도장 찍힘

3. 연속 출석 7일 달성
   → 업적 알림
   "반짝이는 일주일 (7일 연속 출석)"
   → 별조각 +120 획득

4. 무무가 특별 반응
   "무우...!"
   해석: 무무가 꽤 기뻐하는 것 같아요.

5. 출석 캘린더 확인
   → 이번 달 출석 일수: 18일
   → 다음 업적: "별길을 걷는 사람 (누적 30일)"

6. 무무의 애정도 확인
   → affection 75/100 (가까움)
   → 무무가 잎을 흔들며 반응
```

**연결되는 기능:**
- ✅ 출석 체크
- ✅ 연속 출석 업적
- ✅ 누적 출석 추적
- ✅ 캐릭터 애정도 증가

**검증되는 기술:**
- 일일 출석 중복 방지
- 연속 출석 계산 로직
- 업적 진행도 실시간 업데이트

#### 시나리오 3: 소모품으로 캐릭터 돌보기

```
[저녁 9시, 별조각 50개 보유]

1. 상점에서 소모품 구매
   - "별사탕밥" 5개 (5 별조각 × 5 = 25 별조각)
   - "낮잠 쿠션" 3개 (5 별조각 × 3 = 15 별조각)

2. 총 40 별조각 차감

3. 인벤토리 확인
   - 별사탕밥: 5개
   - 낮잠 쿠션: 3개

4. 무무 상태 확인
   → 포만감 40/100 (출출함)

5. "별사탕밥" 사용
   → 수량 -1 (4개 남음)
   → 포만감 +30
   → 무무: "무...! (얌)"

6. 다음 날 아침
   → 무무 상태 다시 낮아짐
   → "별사탕밥" 또 사용

7. 일주일 후
   → 소모품 소진
   → 상점에서 재구매

8. 업적 달성
   "무무의 단골 손님 (소모품 10회 사용)"
   → 별조각 +30 획득
```

**연결되는 기능:**
- ✅ 소모품 구매 (수량 관리)
- ✅ 소모품 사용
- ✅ 인벤토리 관리
- ✅ 소모품 사용 업적

**검증되는 기술:**
- 수량 기반 아이템 관리
- 트랜잭션 관리 (구매/사용)
- 재고 소진 처리

## 6. 크로스 페르소나 시나리오

### 6.1 시나리오: 공유 링크를 통한 바이럴

```
[지우가 인스타그램에 노바 카드 공유]

1. 지우: 노바 카드 공유
   → 공유 링크 생성 (shareId 포함)
   → 인스타그램 스토리에 게시

2. 민준: 지우의 스토리 봄
   → 링크 클릭
   → 앱 설치 페이지로 이동
   → shareId가 localStorage에 저장

3. 민준: 앱 설치 후 회원가입
   → referred_by_share_id에 지우의 shareId 저장

4. 지우: 추천 보상 획득
   → "친구 초대 성공" 업적 달성
   → 별조각 +50 획득

5. 민준: 신규 가입 보상 획득
   → 별조각 +30 획득
   → "친구 추천으로 가입" 배지 획득
```

**연결되는 기능:**
- ✅ 공유 링크 생성 (shareId)
- ✅ 공유 유입 추적 (UTM)
- ✅ 추천인 보상
- ✅ 신규 가입 보상

**검증되는 기술:**
- 공유 이벤트 추적
- referral 연결 로직
- 보상 지급 트랜잭션

---

### 6.2 시나리오: 동시 접속 시 미션 생성

```
[새벽 3시, AI 미션 사전 생성 스케줄러 실행]

1. ai 모듈: 활성 사용자 100명 조회
   → 지우, 민준, 수진 포함

2. 각 사용자별 병렬 처리
   - 지우: 설문 답변 조회 (gRPC)
   - 민준: 최근 완료 미션 조회 (gRPC)
   - 수진: 캐릭터 상태 조회 (gRPC)

3. Spring AI로 미션 생성
   - 지우: "창문 3분 열기" (노바 말투)
   - 민준: "책상 위 물건 하나 치우기" (쪼리 말투)
   - 수진: "오늘 기분 한 단어 적기" (무무 말투)

4. Redis에 캐시 저장
   - key: user:1:missions:today
   - value: [mission1, mission2, mission3...]
   - TTL: 24시간

5. 생성 실패 시 fallback
   - seed 문구 사용
   - ai_generation_logs에 실패 기록

6. 오전 10시, 사용자들 앱 접속
   → Redis에서 미션 즉시 조회
   → 응답 시간 < 100ms
```

**연결되는 기능:**
- ✅ AI 미션 사전 생성 (비동기)
- ✅ 병렬 처리
- ✅ Redis 캐시
- ✅ Fallback 처리

**검증되는 기술:**
- 스케줄러 기반 배치 처리
- gRPC 병렬 호출
- Redis 캐시 전략
- AI API 에러 핸들링
