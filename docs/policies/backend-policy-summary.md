## 1. 인증 정책

| 항목 | 정책 |
| --- | --- |
| 기본 로그인 | Google OAuth2 우선 구현 |

---

## 2. 캐릭터 상태 정책

| 내부 지표 | 화면 표현 | 등급 기준 |
| --- | --- | --- |
| `fullness` | 든든함 / 출출함 / 배고픔 | GOOD: 70~100, NORMAL: 40~69, BAD: 0~39 |
| `energy` | 말짱함 / 졸림 / 피곤함 | GOOD: 70~100, NORMAL: 40~69, BAD: 0~39 |
| `affection` | 가까움 / 조용함 / 쓸쓸함 | GOOD: 70~100, NORMAL: 40~69, BAD: 0~39 |

### 공통 정책

- 내부 수치는 모두 높을수록 좋은 상태로 관리한다.
- 상태 수치는 100을 초과하지 않는다.
- 상태 변화에 따라 캐릭터 이미지가 달라질 수 있다.

## 3. 상태 감소 / 회복 정책

### 상태 감소

| 상태 | 감소 조건 | 감소량 |
| --- | --- | --- |
| `fullness` | 시간 경과 | 6시간마다 -10 |
| `energy` | 시간 경과 / 밤 시간대 | 8시간마다 -10 |
| `affection` | 미션 / 돌봄 / 접속 없음 | 24시간마다 -10 |

### 상태 회복

| 액션 | 회복 지표 | 회복량 |
| --- | --- | --- |
| 밥 주기 | `fullness` | +30 |
| 재우기 | `energy` | +30 |
| 놀아주기 | `affection` | +25 |
| 미션 완료 | `affection` | +5 |
| 출석 | `affection` | +3 |

---

## 4. 돌봄 액션 정책

| 액션 | 비용 | 효과 |
| --- | --- | --- |
| 밥 주기 | 별조각 3개 또는 FOOD 아이템 1개 | `fullness` 회복 |
| 재우기 | 무료 또는 REST 아이템 1개 | `energy` 회복 |
| 놀아주기 | 별조각 2개 또는 TOY 아이템 1개 | `affection` 회복 |

### 정합성

- 별조각이 부족하면 유료 돌봄 액션은 실패한다.
- 소모품 사용 시 `user_items.quantity`를 1 감소시킨다.
- 돌봄 액션은 `character_care_logs`에 기록한다.

---

## 5. 온보딩 설문 정책

- 캐릭터 생성 직후 설문을 시작한다.
- 설문 완료 후 첫 미션을 받을 수 있다.
- 설문 중단 시 홈 진입은 가능하지만, 미션 제안 정확도가 낮다는 안내를 한다.
- MVP에서는 설문 완료를 미션 기능 진입 조건으로 둔다.
- 설문 답변은 AI 미션 추천 데이터로 사용한다.

---

## 6. 미션 제공 정책

- 미션은 한 번에 하나씩 제공한다.
- 오늘 제안된 미션은 stack으로 저장한다.
- 사용자는 현재 미션을 완료하거나 거절할 수 있다.
- 거절하면 다음 미션을 받을 수 있다.
- 하루 최대 제안 수는 15개다.
- 권장 완료 미션 수는 하루 3~5개다.
- 자정에 당일 미션 stack은 만료된다.

---

## 7. 미션 상태 정책

| 상태 | 의미 |
| --- | --- |
| `GENERATED` | 생성됐지만 아직 사용자에게 노출되지 않음 |
| `OFFERED` | 현재 사용자에게 제안된 상태 |
| `REJECTED` | 사용자가 거절 |
| `ANSWERING` | 완료 클릭 후 질문 답변 중 |
| `COMPLETED` | 답변 완료 후 보상 지급 완료 |
| `EXPIRED` | 날짜 변경 또는 제한 조건으로 만료 |

---

## 8. 미션 추천 정책

- 완전 자유 생성이 아니라 `seed 미션 + 점수 기반 개인화 선정 + 캐릭터 말투 변환` 구조로 구현한다.
- 후보 미션은 `active=true`인 템플릿만 사용한다.
- 오늘 이미 완료한 미션은 제외한다.
- 오늘 이미 거절한 동일 템플릿은 제외한다.
- 최근 3회 연속 제안된 동일 템플릿은 제외한다.
- 사용자가 부담된다고 답한 유형은 초반 낮은 우선순위로 둔다.
- 하루 제안 수 15개 초과 시 생성을 중단한다.

---

## 9. 미션 거절 정책

- 거절은 실패로 처리하지 않는다.
- 거절해도 별조각은 차감하지 않는다.
- 거절하면 다음 미션을 받을 수 있다.
- 거절은 하루 제공 미션 수를 차감한다.
- 거절 데이터는 개인화에 사용한다.

---

## 10. 미션 완료 / 답변 정책

- 완료 버튼 클릭 시 미션 상태는 `ANSWERING`이 된다.
- 질문은 1개만 제공한다.
- 답변 방식은 텍스트 입력이다.
- 답변은 최소 1자 이상, 최대 300자 이하로 제한한다.
- 답변 품질을 강하게 판정하지 않는다.
- 욕설 / 비속어는 필터링한다.
- 답변 완료 후 미션 상태는 `COMPLETED`가 된다.
- 완료 후 별조각을 지급하고 상태를 갱신한다.

## 11. 별조각 정책

### 획득처

| 획득처 | 보상 |
| --- | --- |
| 미션 완료 | 10 |
| SNS 공유 | 10 |
| 출석 | 3 |

### 사용처

| 사용처 | 비용 |
| --- | --- |
| 스킨 구매 | 50~100 |
| 밥 아이템 | 3~5 |
| 재우기 아이템 | 5~7 |
| 놀아주기 아이템 | 3~7 |

### 원장 정책

- 별조각 증감은 반드시 거래 내역으로 남긴다.
- 미션 완료 보상은 `missionId` 기준 1회만 지급한다.
- SNS 공유 보상은 하루 1회로 제한한다.
- 아이템 구매 실패 시 별조각은 차감하지 않는다.
- 결제 / 구매를 통한 별조각 지급은 MVP에 없다.

---

## 12. 별조각 구매 제외 정책

MVP에서는 아래를 구현하지 않는다.

- 별조각 구매 화면
- 별조각 구매 API
- Mock 별조각 구매
- 결제 테이블
- PG 연동

---

## 13. 아이템 정책

| 유형 | 정책 |
| --- | --- |
| `SKIN` | 캐릭터 전체 테마 / 색감 |
| `FOOD` | 밥 주기 소모품 |
| `REST` | 재우기 소모품 |
| `TOY` | 놀아주기 소모품 |
| `ACCESSORY` | MVP 제외 |

### 장착 / 구매 정책

- 스킨은 한 번에 하나만 적용한다.
- 보유한 아이템만 적용할 수 있다.
- 스킨은 중복 구매할 수 없다.
- 소모성 아이템은 여러 개 구매할 수 있다.
- 액세서리는 MVP에서 제외한다.

---

## 14. SNS 공유 정책

- 공유용 카드 이미지를 생성한다.
- 이미지 다운로드를 지원한다.
- Web Share API가 가능한 환경에서는 공유하기를 지원한다.
- 공유 버튼 클릭 시 `share_event`를 저장한다.
- 공유 버튼 클릭 시 별조각 10개를 지급한다.
- 공유 보상은 하루 1회만 지급한다.
- 실제 외부 SNS 게시 여부는 MVP에서 검증하지 않는다.
- MVP에서는 `share intent reward`로 처리한다.

---

## 15. 공유 유입 추적 정책

### 수집 / 추적 데이터

- `shareId`
- `shareChannel`
- `referrerUserId`
- `clickCount`
- `signupCount`
- `conversionRate`

### 가입 연결 흐름

```text
공유 링크 클릭
→ share_click 기록
→ localStorage / cookie에 shareId 저장
→ 회원가입 시 referred_by_share_id 저장
→ 공유 기반 가입률 계산
```

---

## 16. 광고 정책

- 광고는 미션 수행 흐름을 방해하지 않는다.
- 광고 배너는 모바일 하단 영역에 배치한다.
- 미션 카드 본문 / 완료 버튼 / 캐릭터 말풍선을 가리지 않는다.
- 광고 로딩 실패 시 빈 영역 또는 house banner를 표시한다.
- 광고 클릭을 유도하는 보상은 MVP에서 제공하지 않는다.
- 광고 노출 / 클릭 이벤트는 기록한다.

---

## 17. 알림 정책

- 앱 내부 알림은 MVP 기본 제공.
- Web Push는 일정에 따라 선택 구현.
- 하루 최대 3회.
- 밤 시간대 제한.
- 사용자가 알림 on/off 가능.
- 죄책감 유발 문구 금지.
- 캐릭터 말투 반영.
